# The Shelf

A full-stack, Dockerised **digital EPUB library** with RBAC (admin / reader), JWT sessions, reading-progress tracking, and a full DevSecOps pipeline (SAST + SCA + DAST).

## Features

| Feature | Detail |
|---|---|
| **Auth** | JWT login/logout, bcrypt passwords, account lockout (5 failed → 15 min lock), inactivity session timeout |
| **RBAC** | `admin` and `reader` roles; separate protected routes per role |
| **Library** | Browse, search, filter by genre, sort, paginate — all server-side |
| **EPUB Reader** | In-browser EPUB.js reader with per-user progress (CFI + %) saved to DB |
| **Admin Dashboard** | Stats cards (books / users / sessions / archived), activity log, CSV export |
| **Admin — Ingest Books** | Manual EPUB upload, batch upload, Project Gutenberg scraper |
| **Admin — Manage Books** | Edit metadata, archive/restore, batch-edit, delete, cover upload |
| **Admin — Manage Users** | List all users, promote/demote roles, unlock locked accounts, delete readers |
| **Profile** | Edit username, change password, reading history with progress bars, delete account |
| **Password Reset** | Email-based token reset (30 min expiry) |
| **HTTPS** | Self-signed certificate on port 3443 (auto-generated by Docker) |
| **Security** | Helmet headers, rate limiting, input validation, CSRF-resistant JWT |

## Quick Start — Local Dev

### Prerequisites
- Node.js ≥ 20
- MongoDB (local or Atlas)

```bash
# 1. Clone
git clone https://github.com/QasimShakir/CyberSecurity_Project.git
cd CyberSecurity_Project

# 2. Install dependencies
npm install

# 3. Configure environment
cp .env.example .env.local
# Edit .env.local — set MONGODB_URI and JWT_SECRET at minimum

# 4. Start the dev server (Vite HMR + Express on port 3000)
npm run dev
```

Open http://localhost:3000 — you will be redirected to the landing page.

> **First run?** See [Admin Setup](#admin-setup-first-run) to create your admin account.

## Quick Start — Docker (Recommended)

Docker Compose starts MongoDB, generates a self-signed TLS certificate, and runs the app — no manual setup required.

```bash
# 1. Clone
git clone https://github.com/QasimShakir/CyberSecurity_Project.git
cd CyberSecurity_Project

# 2. (Optional) set a strong JWT secret
echo "JWT_SECRET=$(node -e \"console.log(require('crypto').randomBytes(64).toString('hex'))\")" >> .env

# 3. Build and start (first run builds the image — takes ~2 min)
docker compose up -d --build --wait

# HTTP  → http://localhost:3000
# HTTPS → https://localhost:3443  (self-signed — accept the browser warning)
```

**Stop:**
```bash
docker compose down          # stop; keep data volumes
docker compose down -v       # stop and delete all data
```

> **First run?** See [Admin Setup](#admin-setup-first-run) to create your admin account via the seed endpoint.

## Admin Setup (First Run)

All new users created through `/signup` receive the `reader` role. You need **one** admin to unlock the Admin panel.

### Option A — Seed endpoint (easiest, works with Docker)

The `/api/setup/seed` endpoint creates the first admin account. It is a one-time operation — it returns `409 Conflict` once an admin already exists.

```bash
curl -s -X POST http://localhost:3000/api/setup/seed \
  -H "Content-Type: application/json" \
  -d '{"username":"Admin","email":"admin@example.com","password":"StrongPass123!"}' \
  | python3 -m json.tool
```

The response includes a JWT token you can use immediately. The endpoint is automatically disabled once any admin exists.

### Option B — MongoDB shell (Atlas or local)

```js
db.users.updateOne(
  { email: "your@email.com" },
  { $set: { role: "admin" } }
)
```

## Environment Variables

Copy `.env.example` to `.env.local` (local dev) or set these as Docker environment variables.

| Variable | Required | Default | Description |
|---|---|---|---|
| `MONGODB_URI` | ✓ | `mongodb://localhost:27017/the-shelf` | MongoDB connection string |
| `JWT_SECRET` | ✓ | `your-secret-key` | JWT signing secret — **change in production** |
| `SESSION_DURATION` | | `24h` | Token lifetime (e.g. `1h`, `24h`, `7d`) |
| `NODE_ENV` | | `development` | Set to `production` in Docker |
| `APP_BASE_URL` | | `http://localhost:3000` | Public URL used in password-reset emails |
| `EMAIL_USER` | | — | Gmail address for password-reset emails |
| `EMAIL_PASS` | | — | Gmail app password |

Generate a strong secret:
```bash
node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"
```

## Role-Based Access Control

| Page / Route | Reader | Admin |
|---|---|---|
| `/landingpage` | ✓ | ✓ |
| `/login`, `/signup` | ✓ | ✓ |
| `/library` | ✓ | ✓ |
| `/book/:id` | ✓ | ✓ |
| `/read/:id` | ✓ | ✓ |
| `/profile` | ✓ | ✓ |
| `/admin` | ✗ | ✓ |
| `/admin/ingest` | ✗ | ✓ |
| `/admin/manage` | ✗ | ✓ |
| `/admin/users` | ✗ | ✓ |

Unauthenticated users are redirected to `/login`. Authenticated readers attempting admin routes are redirected to `/library`. Role checks are enforced on both the React router guard (`ProtectedRoute`) and every backend API endpoint (`isAdmin` middleware).

## DevSecOps Pipeline

Three independent CI jobs run on every push and pull request to `main`:

### Stage 1 — SCA (Software Composition Analysis)
- Tool: **npm audit**
- Checks all dependencies for known CVEs
- Quality gate: **fails** if any `critical` or `high` vulnerability is found
- Artifact: `sca-npm-audit.json`, `sca-npm-audit-readable.txt`

### Stage 2 — SAST (Static Application Security Testing)
- Tool: **Semgrep** (`p/nodejs`, `p/jwt`, `p/xss`, `p/javascript`, `p/typescript`)
- Scans source code for security anti-patterns
- Quality gate: **fails** if any `ERROR`-severity finding is reported
- Artifact: `sast-semgrep-report.json`, `sast-semgrep-readable.txt`

### Stage 3 — DAST (Dynamic Application Security Testing)
- Tool: **OWASP ZAP** baseline scan
- Builds the full Docker image, starts the stack via `docker compose up --wait`, then scans `http://localhost:3000`
- Quality gate: reports High / Medium / Low counts; warns on High findings
- Artifact: `report_html.html`, `report_json.json`, `report_md.md`
